## 已实现的端侧 AI 能力

- 学习最多 32 个 CAN ID 的正常画像。
- 记录每个 ID 的周期、周期抖动、DLC 和 Payload 基线。
- 检测未知 ID、DLC 改变、周期过快/过慢、Payload 跳变和总线洪泛。
- 输出 0～1000 的异常分数和原因位掩码。
- 支持学习、监测、内部回环和合成攻击演示模式。
- 检测结果在 RA8D1 本地生成；上位机不替代端侧推理。

这是一种**可解释的在线统计异常检测**，不是预训练神经网络。它回答的是“当前流量是否偏离已学习的正常流量”，而不是“这条 CAN 信号在车辆语义上代表什么”。

## 当前限制与风险

1. **真实 CAN 总线仍需第二节点验收。** 回环和合成流量不能证明 CANH/CANL、收发器、终端电阻、ACK、线束和 EMC 都正确。
2. **模型只在 RAM 中。** 复位后需要重新学习，暂无 Flash 持久化、版本校验和回滚。
3. **没有 DBC 语义。** 当前检测 ID 和字节行为，不解析车辆信号物理量。
4. **FDF/BRS/ESI 还不是独立检测特征。** UI 会显示它们，但模型没有把每一项单独纳入异常判定。
5. **高负载下串口遥测会占用主循环。** 生产版本应改为 DMA/非阻塞遥测，并增加 FIFO 深度和压力测试。
6. **不具备功能安全属性。** 不能直接用于汽车安全决策、量产网关或安全保护闭环。

## 建议的下一阶段

### 阶段 1：补齐真实总线验证

- 准备第二个 CAN/CAN-FD 节点或 USB-CAN-FD 适配器。
- 验证 500K 仲裁、2M 数据段、ISO CAN-FD、终端约 60 Ω、ACK 和 Bus-Off 恢复。
- 记录正常流量、未知 ID、周期攻击、DLC 攻击和 Payload 攻击的误报/漏报。

### 阶段 2：提高工程可信度

- 增加 Flash 模型存储、CRC、模型版本和显式重新学习命令。
- 增加 SEQ 字段，避免同一毫秒内多帧被上位机去重。
- UART 改为 DMA/非阻塞，做 1k～2k fps 压力测试并报告 DROP 边界。

### 阶段 3：增加行业语义

- 引入 DBC 解码和信号级规则。
- 统计不同车型/节点/工况的域偏移。
- 再考虑轻量神经网络或量化模型，而不是直接把统计检测改成不可解释的黑盒。
